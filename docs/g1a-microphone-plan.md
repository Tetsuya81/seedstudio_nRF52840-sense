# G1A: Phase 2 マイク測定計画

**位置づけ**: G0 は「経路が生きているか」の smoke であり、Phase 2 の測定ではない。
本計画は roadmap の Phase 2（ノイズフロア、クリップ点、ハンドリングノイズ、
キャビティ＋ダクト、AGC/HPF の要否）を実際に測るための手順である。

**前提**: `docs/collab/HARDWARE_HOLD` は継続。本計画の実施には
**G0 とは別の scope**（複数回の upload と serial session）が要る。
G0 の token（upload 1 / serial-read 1）では実施できない。

**録音フラッシュに触れない**: 全ステージで QSPI / MSC / FatFs を初期化しない。
G1A 専用イメージの条件は MSG-055 §3 のとおり。

---

## 0. 測定の出し方（先に決めておく設計事項）

`[推測]` 生 PCM をそのままシリアルへ流すと、16kHz/16bit で 32,000 B/s になる。
CDC なので名目 baud は無関係だが、ホスト側の取りこぼしを避けたい。

したがって**2系統に分ける**。

| 種別 | 内容 | 用途 |
|---|---|---|
| **統計量**（常時） | RMS / peak / clip count / DC offset / 帯域別エネルギー / overflow・drop count | 数値で比較する測定（Stage 1〜4） |
| **生波形**（短時間のみ） | 10秒の raw PCM をバイナリ枠で転送 | ホストでの AB 比較（Stage 5） |

`[推測]` 生波形は base64/hex にすると 2〜3 倍になるので**生バイナリ**で送る。
10秒 = 320,000 B。USB FS のバルク転送なら数秒で済む見込み（**未実測**）。

各ステージの出力は**その場でファイルへ追記**し、セッションが切れても残す。

---

## Stage 1 — ベースライン（基板を机上に置いたまま）

**目的**: マイク単体の素の性能を知る。以後のすべての比較の基準になる。

| 測定 | 手順 | 得られるもの |
|---|---|---|
| ノイズフロア | 静かな部屋で30秒。無音のまま | RMS の dBFS。以後の SN 計算の分母 |
| ゲイン特性 | `PDM.setGain()` を 20 / 30 / 40 で各10秒 | クリップとノイズフロアのトレードオフ |
| クリップ点 | 30cm・40cm × 通常音量・大声 の4条件で各10秒 | peak が 0 dBFS に達する条件 |
| DC オフセット | 上記すべてで記録 | HPF の要否 |

**判断すること**: 既定ゲイン20が妥当か。HPF を入れるか。

`[実測・既知]` 参考値: 起動直後の 500ms で RMS 683 / peak 7890（-33.6 / -12.4 dBFS）。
ただしこれは環境音を含む1回の観測で、ノイズフロアの測定ではない。

---

## Stage 2 — 指の位置での収音

**目的**: 口元から 30〜40cm 離れ、常に動く場所にマイクがある条件での SN を知る。

**固定方法**: 基板ごと人差し指に固定する（写真の装着方法をそのまま使う）。
マイクをリード線で延ばす案は、配線が増えて G1A の「外部配線なし」条件に反するので採らない。

Stage 1 と**同じ測定を装着状態で**行い、差分を見る。

**判断すること**: 机上との SN の差。実用に足りるか。
**ここが Phase 2 の主目的**であり、足りなければ設計全体を見直す。

---

## Stage 3 — ハンドリングノイズ

**目的**: 機械的なノイズが音声をどれだけ潰すかを知る。

各動作を10秒ずつ、**無発話**と**発話中**の両方で:

1. 手を静かに握る / 開く
2. 指を曲げる
3. 衣服に擦れる
4. キーボード打鍵
5. 歩行

**得られるもの**: 各動作の peak / RMS、発話中の SN 低下量。

**判断すること**: 機械的な緩衝（ガスケット、マイクの浮かせ方）が要るか。
筐体設計（`ring-design.md`）に直結する。

---

## Stage 4 — キャビティ＋ダクトの影響

**目的**: `ring-design.md` 5節の音道がヘルムホルツ共鳴で音を色付けるかを見る。

**模擬方法**: 厚紙とテープで、基板下 1mm の空隙と側面への短いダクトを簡易に作る。
3Dプリントを待たずに傾向だけ掴む。

| 条件 | 測定 |
|---|---|
| ダクトなし（基準） | 帯域別エネルギー |
| ダクトあり | 同上。差分が共鳴の目安 |

**判断すること**: 共鳴が実用上問題になるか。ダクトの寸法をどちらへ振るか。

---

## Stage 5 — 符号化方式の判断材料

**目的**: MSG-003 で合意した AB 比較の素材を採る。

**手順**:

1. Stage 2〜3 の条件で、**生 PCM を10秒ずつ**取得（静かな部屋 / 屋外・店内 / 歩行 / 衣服擦れ / 小声）
2. ホスト上で 16kHz ADPCM / 8kHz ADPCM / Opus 12k・16kbps を生成
3. ファイル名をランダム化して聴く
4. **「好み」ではなく**、第三者の文字起こし正答率、固有名詞・数字の復元、
   本人が翌日に用件を実行できたかで判定する

**判断すること**: 符号化方式。**これが決まると最小保存長のUX仕様も確定する**
（MSG-048 の結合。`MIN_SAVED_AUDIO_BYTES >= 12,193` を満たす秒数が方式ごとに変わる）。

---

## 実施上の規律

各 Stage は**1操作ずつ**行い、結果を確認してから次へ進む。

- upload / serial session は scope token で回数を制限する（G0 と同じ機構）
- セッションは受信専用。ホストから文字を送らない
- 異常（Mac の freeze、発熱、臭い、予期しない再列挙）で即座に中止し、
  `HARDWARE_HOLD` 全面状態へ戻す
- 各 Stage の出力は即時ファイルへ追記

## 中止条件

- Stage 2 で装着時の SN が実用に耐えないと判明した場合、
  **Stage 3 以降へ進む前に設計へ戻る**（マイク位置、指向性、機械設計の見直し）
- overflow / drop が発生する場合、測定値は信用せず先に原因を潰す
