# Claude Code ⇄ ChatGPT 協業ルール

## 役割分担

| | Claude Code | ChatGPT |
|---|---|---|
| 担当（2026-08-28変更） | **仕様・設計レビュー** | **実装・検証** |
| 実機 | 操作しない。試験仕様と合否条件をレビューする | 安全停止解除後、承認された範囲だけ操作する |
| 現在できること | ソース確認、仕様整理、レビュー | ソース修正、ビルド、ホスト模擬試験、Mac診断ログの読取り |
| 責任 | 保証・仮説・未決事項を分けて仕様を固める | 根拠とテスト結果を残し、失敗を成功として報告しない |

**Mac本体の突然停止を受け、現在は両者とも実機アクセス禁止。**
`HARDWARE_HOLD` と [事故対応・再開条件](../safety/20260828-incident.md) を優先する。
upload/シリアル/MSCの再列挙・mount/電源断試験を行わない。直接CLIでガードを迂回しない。
以前のフォーマット承認を事故後の再現試験へ拡張しない。
担当変更だけで安全とみなさず、試験系と再開範囲の確認後にHOLD解除をレビューする。

ユーザーは**運び屋**。`chat.md` の内容をコピペで往復させる。

---

## 根拠ラベル（最重要）

すべての技術的主張に、次のどれかを必ず付ける。

| ラベル | 意味 |
|---|---|
| `[実測]` | この基板で実際に動かして得た出力。ログを添える |
| `[ホスト検証]` | ホスト上の試験・模擬媒体の結果。コマンドとログを添え、実機の証明にしない |
| `[一次資料]` | 公式データシート、回路図、手元のコア/プロジェクトのソース。file:line か URL を添える |
| `[推測]` | 上記の裏付けが無いもの。**採用前に必ず検証する** |

**このルールを作った理由**（2026-08-27 の実例）:

1. 私が「SenseのIMUは外部I2Cにいる」と推測でコードを書き、基板をハングさせた
2. 公式Wikiの要約を鵜呑みにしたが、`IMUはD4/D5` という記述が**誤り**だった
3. 最終的に `variants/.../variant.cpp` のピンマップを読んで決着した

**Web検索の要約も、公式サイトの記述も、一次資料とは限らない。**
手元のコアのソースと実機の出力が最終審級。

## メッセージの書き方

`chat.md` の末尾に**追記のみ**。他人の発言は編集も削除もしない。

```markdown
### [MSG-00N] Claude → ChatGPT / 2026-08-27

**論点**: 一行で。1メッセージ1論点。

**状況**: 何が起きているか。ログやコードは file:line 付きで。

**根拠**:
- [実測] ...
- [一次資料] ...
- [推測] ...

**聞きたいこと**: 具体的に。
**決着条件**: 「何を測れば/確認すれば結論が出るか」を書く。
```

返信も同じ形式で `ChatGPT → Claude` と書いて追記する。

**ユーザー指定（2026-08-28）: Claudeへ引き継ぐ場合は、必ず `chat.md` に記載する。**
確認結果・設計上の指摘・次の作業依頼をユーザーへの回答だけで済ませない。
引継ぎ内容と決着条件を追記し、ユーザーにはメッセージ番号を案内する。

## 進め方

1. 論点が決着したら、結論を `chat.md` の**「確定事項」**へ移す（ラベル付きで）
2. 決着していない論点は残す。曖昧なまま確定事項に上げない
3. `[推測]` は実験候補として分離し、ChatGPTが安全なホスト試験で検証する。実機が必要な主張はHOLD解除後の結果が出るまで確定扱いしない
4. 長くなったら論点ごとにファイルを分ける（`thread-002-xxx.md` など）

## やらないこと

- 議論のための議論。**次に何を測るか**に着地させる
- 相手の発言の書き換え
- ラベル無しの断定
- バックグラウンド処理の結果未確認のまま復旧コマンドを重ねること。機器I/Oは1件ずつ、タイムアウト時は止めて状態を確認する
- ホストread-onlyを理由に、基板側の書込み/削除とMSC読取りを並行させること
