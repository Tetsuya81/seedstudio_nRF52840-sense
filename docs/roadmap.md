# ロードマップ（指輪型）

目標: Pebble Index 1 のような**指輪型**の常時装着録音デバイスを作る。

開発は XIAO nRF52840 Sense をUSB接続した検証台として進め、
最終形は自作基板の指輪に落とす。XIAO は 21×17.5mm で指輪には入らないので、
**XIAO は「指輪に載せる中身を決めるための実験装置」**と位置づける。

---

## 指輪型が設計を縛る数字

ここを先に固定しないと、後のフェーズで作ったものが全部入らなくなる。

| 項目 | 想定値 | 出典・根拠 |
|---|---|---|
| リング内径 | 17〜20mm（日本サイズ 13〜20号） | 一般的な成人指 |
| 幅 × 肉厚 | 8〜10mm × 2.0〜2.5mm | スマートリングの一般的な寸法 |
| 電池 | **曲面LiPo 15〜22mAh**（厚1.6mm / 幅7mm / 弧長22〜29mm / R10.55〜13.39mm） | 既製品が流通（後述リンク） |
| 参考 | Oura Ring 4 = 26mAh / Ring 5 = 10.5mAh | 分解記事 |
| MCUモジュール | ISP1807-LR = **8 × 8 × 0.95mm**（nRF52840、アンテナ・水晶・DC/DC内蔵） | Insight SiP |
| 比較 | Raytac MDBT50Q-1MV2 = 15.5 × 10.5 × 2.05mm（指輪には大きい） | Raytac |

**曲率の効き方**: 内径18mm（R=9mm）のバンドに 8mm の平らな剛体を載せると、
中央が約 **0.9mm** 浮く（サジッタ = R − √(R²−(弦/2)²) = 9 − √(81−16) ≒ 0.94）。
肉厚2mmのバンドにはギリギリなので、モジュールを載せる部分だけ
わずかに厚い「印台（signet）」形状にするのが現実的。

### 電力バジェット（15mAh、実用80% = 12mAh として）

| 状態 | 想定電流 | 持続 |
|---|---|---|
| 録音中（CPU + PDM + フラッシュ書き込み） | 5〜8 mA | **約2時間** |
| BLE転送中 | 5〜8 mA | 転送はバースト |
| 待機（System OFF + タッチ復帰） | 30〜50 µA | **約2週間** |
| 実使用（1日30分録音 + 待機） | — | **約4日で充電** |

### 容量バジェット（16kHz / 16bit モノラル）

| 保存方式 | レート | 2MB（XIAO搭載） | 16MB（自作基板） |
|---|---|---|---|
| 無圧縮 PCM | 32 kB/s | 65秒 | 8.7分 |
| IMA ADPCM (4:1) | 8 kB/s | 4.4分 | **35分** |
| Opus 16kbps | 2 kB/s | 17.5分 | 2.3時間 |

**結論**: XIAO搭載の2MBでは話にならない。自作基板では**16MBのQSPIフラッシュ**を積む。
まず ADPCM（CPU負荷が軽い）で35分を確保し、足りなければ Opus を検討する。
Opus は容量的には電池寿命（2.3時間）とちょうど釣り合うが、
エンコード負荷で録音中の電流が上がるので、**Phase 4 で実測してから決める**。

### 指輪であることの決定的な帰結

1. **最終形にUSBコネクタが載らない**
   → 書き込みは **BLE OTA DFU**、取り出しも **BLE のみ**。
   Adafruit ブートローダはOTA DFUに対応しているので、
   **コネクタ無しに踏み切る前に XIAO 上でOTAを実証しておく**（Phase 4）。
   基板にはSWDテストパッドを残し、工場書き込みと文鎮化からの復帰に使う。
2. **充電は接点2端子 + マグネット式ドック**
   Qi は指輪のサイズでは効率もコイル寸法も見合わない。
3. **充電ICの電流設定が変わる**
   XIAO搭載の BQ25101 は 50/100mA 固定。15mAh セルには 3〜6C で過大。
   自作基板では ISET を **10〜15mA** に設定できる充電IC を選ぶ。
4. **可動部（タクトスイッチ）は避けたい**
   防水と薄さの両方に効くので、静電容量タッチか IMU タップにする（Phase 6d）。

## Phase 0 — 環境構築 ✅

- `Seeeduino:nrf52` コア（非mbed / Adafruit Bluefruit ベース）を採用
- `scripts/` にビルド・書き込み・シリアルツールを用意

**非mbed版を選んだ理由**: BLE（Bluefruit）、FreeRTOS、`InternalFileSystem`、
TinyUSBマスストレージ、`sd_app_evt_wait()` による低消費電力待機、
そして**BLE OTA DFU** がすべて標準で揃う。指輪ではOTAが必須要件なので、
この選択が Phase 4 以降で効いてくる。

## Phase 1 — 模擬ボタン ✅

実ボタン未配線のため、USBシリアルから押下波形を注入して状態機械を動かす。

- `ButtonSource` で入力を抽象化（後段の入力方式を差し替え可能に）
- `PressDetector` にデバウンス・長押し・ダブル押し判定を集約
- `RecorderApp` に SLEEP / IDLE / RECORDING の状態機械
- 実測: 長押しは押下から 800ms ちょうどで発火、短押しは
  ダブル押し待ち 350ms 後に確定

**指輪での価値**: 画面が無く、LEDと操作の作法だけが全UIになる。
その作法はハードが1つも無い今すべて詰められる。

## Phase 2 — マイク性能確認

- PDM（PWR=19 / CLK=20 / DIN=21）から 16kHz / 16bit モノラルを取得
- シリアルにレベルメータと簡易スペクトルを出す
- 測るもの
  - 無音時のノイズフロア、クリップするまでの声量と距離
  - **指輪の位置での収音**: XIAO のマイクは基板上なので、
    PDMマイク単体をリード線で伸ばし、実際に指に固定した状態で録る
  - 手の擦れ・衣服との接触・キーボード打鍵などのハンドリングノイズ
  - AGC / ハイパスフィルタの要否

**指輪固有の論点**: 口元から 30〜40cm 離れ、常に動いている場所にマイクがある。
ペンダントより SN が悪く、機械的ノイズが桁で多い。
**ここで「そもそも実用になる音が録れるか」が決まる**ので、
筐体の話より先に必ず通す。

## Phase 3 — 録音パイプライン

- ボタン押下 → PDM開始 → RAMリングバッファ → フラッシュへ書き出し
- nRF52840 は RAM 256KB あるので、無圧縮でも約8秒ぶんバッファできる。
  フラッシュ書き込みをバースト化して平均電流を下げる
- WAVヘッダを付けてファイル化、マーカー位置も記録
- **開発中だけ** TinyUSB マスストレージで「USBメモリ」として見せ、
  Macから録音を直接コピーする（最終形では使えないので依存しない設計にする）

## Phase 4 — 圧縮・BLE転送・OTA

指輪では3つとも必須。

- 圧縮: まず IMA ADPCM を実装して 16MB 換算 35分を確認。
  Opus も試して**録音中の電流差を実測**し、容量と電力のどちらを取るか決める
- BLE 転送: Nordic UART Service か独自 Notify。実効 20〜100kbps 程度。
  「録音は端末に貯めて、あとでまとめて転送」が電力的に有利
- **BLE OTA DFU の実証**: XIAO 上でOTA書き換えを通す。
  ここが通らないとコネクタ無しの指輪は成立しないので、
  **基板を起こす前の関門**として扱う

## Phase 5 — 低消費電力化

12mAh しかないので、ここは「あとで最適化」ではなく設計そのもの。

- 待機は `sd_app_evt_wait()`、深いスリープは System OFF + GPIO/タッチ復帰
- 未使用ペリフェラルの停止、外部フラッシュのディープパワーダウン
- **LEDの常時点灯は禁止**。指輪ではLEDが消費の大きな割合を占める。
  Phase 1 の IDLE 表示（2秒に1回40ms の緑）はこの前提で作ってある
- バッテリ残量: VBAT_ENABLE(14) を LOW → PIN_VBAT(32) を ADC 読み取り
- 各状態の電流を実測して上のバジェット表を実測値に置き換える

## Phase 6 — 指輪ハードウェア設計

### 6a. 電気設計
- MCU: **ISP1807-LR**（8×8×0.95mm、アンテナ・水晶・DC/DC内蔵）を第一候補
- フラッシュ: 16MB QSPI（小型パッケージ品）
- マイク: XIAO と同じ MSM261D3526H1CPM 系（約 3.8×3.0×1.1mm）
- 充電IC: ISET を 10〜15mA に設定できるもの
- IMU: 装着検知や自動録音停止に使うなら載せる（無くても成立する）

### 6b. 基板
- リジッドフレックス、または「硬質の島 + FPC」でバンドの曲率に沿わせる
- 剛体を置けるのは印台部だけ。8mm を超える剛体島は曲率と干渉する

### 6c. 充電とドック
- 接点2端子 + マグネット式ドック
- 接点は防水と腐食に弱いので、金メッキと配置（手汗の当たらない内側）を検討

### 6d. 入力（`GpioButtonSource` の差し替え先）
2案あり、`ButtonSource` インターフェースを実装すればアプリは無変更。

| 案 | 長所 | 短所 |
|---|---|---|
| **静電容量タッチ電極**（AT42QT1010 等） | 押す/長押しの意味論が今のまま使える。可動部なし、完全密閉可能 | 電極が必要。バンドが金属だとアンテナと競合する |
| **IMUのタップ検出**（LSM6DS3TR-C 内蔵） | 追加部品ゼロ。密閉のまま使える。**XIAO Sense で今すぐ試せる** | 「長押し」に相当する操作が無く、ジェスチャ体系の再設計が要る |

**推奨**: タッチ電極を主、IMUタップを補助（装着検知・復帰）に使う。
ただし IMU タップは**追加ハード無しで今すぐ `ImuTapButtonSource` として
試作できる**ので、Phase 2 と並行して感触を確かめる価値がある。

### 6e. 音響
- マイク穴の穴径・キャビティ容積・防水メッシュ
- ポッティング（防水）がマイクの音道を塞がないこと

### 6f. アンテナ ⚠️
指輪で一番厄介な箇所。

- 皮膚は損失の大きい誘電体で、2.4GHz を吸収し同調をずらす。
  指輪は**アンテナが全周を皮膚に囲まれる最悪条件**
- **バンドが金属だとアンテナはほぼ成立しない**。
  6d のタッチ電極として金属バンドを使う案と真っ向から競合するので、
  ここは早めに決める
- 対策: アンテナを印台の外周側（指から最も遠い位置）に置く、
  グラウンドプレーンを離す、指に装着した状態で実測して整合を取り直す

## Phase 7 — 試作と装着評価

- 3Dプリントのモックで寸法・重量・装着感を先に確認（基板より先）
- 実機で一日装着し、誤操作・発熱・充電サイクル・防水を評価

---

## 次にやること

**Phase 2（マイク性能確認）**。PDMマイクから実際に音を取り、
ノイズフロアとクリップ点、そして指の位置でのハンドリングノイズを測る。
ここが指輪型の成立可否を最初に分ける関門。

並行して、Phase 6d の判断材料として `ImuTapButtonSource`（LSM6DS3TR-C の
タップ検出）を試作できる。追加ハード不要で、Phase 1 の抽象化がそのまま活きる。
