# ロードマップ（指輪型）

目標: Pebble Index 1 のような**指輪型**の常時装着録音デバイスを作る。

物理設計の詳細は **[docs/ring-design.md](ring-design.md)** を参照。

---

## 2段構えで進める

| | v1 | v2 |
|---|---|---|
| 中身 | **XIAO をそのまま TPU リングに収める** | 自作基板で小型化 |
| 基板 | 既製（21×17.5mm） | ISP1807-LR 等（8×8×0.95mm） |
| USB-C | **残す**（書き込み・充電・取り出し） | 載らない → BLE OTA と充電ドックが必須 |
| 電池 | 基板脇のくさび空隙に 約40mAh | 曲面LiPo 15〜22mAh |
| フラッシュ | 2MB（**録音数分で頭打ち**） | 16MB |
| 位置づけ | **今あるハードで最後まで組める** | v1 で仕様が固まってから |

**v1 で自作基板が要らないのが、この設計方針の一番大きい効果。**
以下の Phase は特記なければ v1 の話。

### v1 で前提が変わった3点

1. **BLE OTA DFU は不要になった** — USB-C を残せるので、書き込みも取り出しも従来どおり。
   以前は「基板を起こす前の関門」としていたが、**v2 に降格**する
2. **電池の心配が減り、容量が前面に出た** — くさび空隙に約40mAh 入り録音5時間分あるが、
   2MB フラッシュは ADPCM でも 4.4分しか入らない。**保存容量が先に尽きる**
3. **アンテナ問題がほぼ消えた** — TPU は非導電。金属バンド案との競合が無くなった

---

## Phase 0 — 環境構築 ✅

- `Seeeduino:nrf52` コア（非mbed / Adafruit Bluefruit ベース）を採用
- `scripts/` にビルド・書き込み・シリアルツールを用意

**非mbed版を選んだ理由**: BLE（Bluefruit）、FreeRTOS、`InternalFileSystem`、
TinyUSBマスストレージ、`sd_app_evt_wait()` による低消費電力待機が標準で揃う。
（BLE OTA DFU 対応も理由の一つだったが、v1 では使わない。v2 で効いてくる）

## Phase 1 — 模擬ボタン ✅

実ボタン未配線のため、USBシリアルから押下波形を注入して状態機械を動かす。

- `ButtonSource` で入力を抽象化。**物理ボタンを使うと決まったので、
  差し替え先は `GpioButtonSource`（実装済み）で確定**
- `PressDetector` にデバウンス・長押し・ダブル押し判定を集約
- `RecorderApp` に SLEEP / IDLE / RECORDING の状態機械
- 実測: 長押しは押下から 800ms ちょうどで発火、短押しは
  ダブル押し待ち 350ms 後に確定
- `m` コマンドで基板の自己診断（Sense版かどうかを IMU の WHO_AM_I で判定）

**指輪での価値**: ディスプレイを持たない方針なので、LEDと操作の作法だけが全UIになる。
その作法はハードが1つも無い今すべて詰められる。

## Phase 2 — マイク性能確認 ← 次

- PDM（PWR=19 / CLK=20 / DIN=21）から 16kHz / 16bit モノラルを取得
- シリアルにレベルメータと簡易スペクトルを出す
- 測るもの
  - 無音時のノイズフロア、クリップするまでの声量と距離
  - **指輪の位置での収音**: 実際に指に固定した状態で録る
  - 手の擦れ・衣服との接触・キーボード打鍵などのハンドリングノイズ
  - **キャビティ＋ダクトの影響**（ring-design.md 5節）。
    基板を1mm浮かせて側面へ導く音道がヘルムホルツ共鳴で音をどう色付けるか
  - AGC / ハイパスフィルタの要否

**指輪固有の論点**: 口元から 30〜40cm 離れ、常に動いている場所にマイクがある。
SN が悪く機械的ノイズが多い。**ここで「実用になる音が録れるか」が決まる**ので、
筐体を印刷する前に必ず通す。

## 実機検証のゲート（2026-08-29 追加）

Mac の突然停止を受けて実機アクセスを停止（`docs/collab/HARDWARE_HOLD`）しているが、
**ホスト検証だけで無期限に進めない。** 段階ごとに実機で確かめる。
詳細と合否条件は `docs/collab/chat.md` の MSG-020。実施は ChatGPT。

| 段 | 内容 | 破壊性 |
|---|---|---|
| G0 | HOLD 解除（事故レビュー完了とユーザー承認） | — |
| G1 | 実機スモーク。書込みなしの読み出し確認 | なし |
| G2 | 新ジオメトリ（au=4096＋索引予約）での初期化と基本書込み | あり |
| G3 | 隣接・断片化・削除・再利用で Tier A が毎回回収できるか | あり |
| G4 | MSC 所有権と領域分離（FAT操作が索引を触らないこと） | あり |
| G5 | 電源断。**ホストを接続しない**（充電専用ケーブル＋電源アダプタ） | あり |
| G6 | 長時間・満杯・索引満杯の境界 | あり |

**原則**: 各段の対応するホスト失敗注入が全点PASSしてから、その段の実機へ進む。
**停止条件**: Tier A（停止済み録音）が1本でも失われたら、その段で止めて設計に戻る。

## Phase 3 — 録音パイプライン

- ボタン押下 → PDM開始 → RAMリングバッファ → フラッシュへ書き出し
- nRF52840 は RAM 256KB あるので無圧縮でも約8秒ぶんバッファできる。
  フラッシュ書き込みをバースト化して平均電流を下げる
- WAVヘッダを付けてファイル化、マーカー位置も記録
- TinyUSB マスストレージで「USBメモリ」として見せ、Macから直接コピー
  （v1 は USB-C を残すので、これが正式な取り出し手段になる）
- ⚠️ **コア同梱の `ExternalFS` をそのまま使ってはいけない**。
  `ExternalFileSystem.cpp:141` の `flash.begin(&P25Q32H, 1)` は
  実チップ P25Q16H (JEDEC `0x856015`) と一致せず **`false` を返す**が、
  戻り値が確認されていない。フォールバック用の `possible_devices[]`
  (`Adafruit_SPIFlashBase.cpp:91-101`) にも P25Q16H は無いため救済されない。
  結果 `_flash_dev == NULL` / `size() == 0` のまま後段が動く＝**初期化直後から未定義**。
  対策は `Adafruit_SPIFlash` を直に使い、**P25Q16H を含む許可リストを渡して
  `begin()` の戻り値を必ず確認**すること。`flash.size()` は照合に成功した
  記述子の値を返すだけなので、許可リスト無しでは未知チップに自動対応しない
- ファイルシステムは **FAT12 + USB MSC**。2MiB は 512B/sector で 4096 sector しかなく、
  クラスタ数が 4085 未満になるため標準準拠の選択肢は FAT12 のみ。
- ⚠️ **クラスタは 4KiB（au=4096）にする。** 1KiB だと1つの消去ブロックに
  4クラスタ＝最大4本の録音が同居し、新しい録音の書込みで保存済み録音が失われ得る。
  au=4096 なら 1クラスタ = 1消去ブロックで非共有になる（`tools/fatfs_host` で実測）
- ⚠️ **保存済み録音の生存を FAT に依存させない。** 各 4KiB ブロックを自己記述にし
  （magic + recId + blockIndex + CRC32）、完了記録は FAT の外の追記専用索引へ置く。
  これにより FAT/root/BPB が全損しても、媒体を走査するだけで全録音を再構成できる。
  形式と書込み順序は MSG-020 を参照
  ただしコア同梱の `FatFormatter` は 6MB 以下を拒否する (`FatFormatter.cpp:55-57`) ので、
  自前の最小フォーマッタか検証済みイメージが要る

## Phase 4 — 圧縮（v1の最大の関門）

電池は5時間もつのに、2MB フラッシュは無圧縮65秒。**ここが v1 の勝負どころ。**

| 保存方式 | 2MiB で録れる長さ（実測容量から算出） | CPU負荷 |
|---|---|---|
| IMA ADPCM 16kHz (4:1) | **4m22s** | 軽い |
| IMA ADPCM 8kHz | **8m44s**（PDMが8kHz非対応のためデシメーション必要） | 軽い |
| Opus 16kbps | **17m28s** | 重い |

> これは1セッションの長さではなく**全録音の合計容量**。
> なお 2MiB を1回埋める間の電池消費は約0.44mAh（実用32mAhの1.4%）で、
> **セッション内では電池は制約にならない**。効くのは USB退避までの間隔。

- まず **ADPCM** を実装してパイプライン全体を通し、4.4分を実測で確認する
- そのうえで、狙う1セッションの長さに応じて次を選ぶ
  - 4分で足りる（一言メモ用途）→ ADPCM のまま完成
  - もっと欲しい → **Opus**（17.5分。ただし電流を実測して電池と釣り合うか確認）
  - さらに欲しい → 外付けSPIフラッシュ（16MB）を D8/D9/D10 に増設。
    ただし指輪の中に部品が増えるので v2 の話に近づく
- BLE 転送は v1 では必須ではない（USBで取り出せる）が、
  実装しておくと使い勝手が大きく変わる

## Phase 5 — 低消費電力化

- 待機は `sd_app_evt_wait()`、深いスリープは System OFF + **D1 の GPIO DETECT** で復帰
- 未使用ペリフェラルの停止、外部フラッシュのディープパワーダウン
- **LEDの常時点灯は禁止**。Phase 1 の IDLE 表示（2秒に1回40msの緑）はこの前提
- バッテリー残量: VBAT_ENABLE(14) を LOW → PIN_VBAT(32) を ADC 読み取り
- 充電電流は **P0.13 を HIGH（50mA）で固定**。100mA は小型セルに過大
- 各状態の電流を実測してバジェット表を実測値に置き換える

## Phase 6 — v1 組み立て

手順と設計値は **[docs/ring-design.md](ring-design.md)** に集約。要点だけ:

1. `x` で LED の載っている面を確認 → 外向きに決める
2. マイクの載っている面を目視確認 → 音道の設計を決める
3. タクトスイッチを **D1–GND** に配線（`INPUT_PULLUP`）
4. TPU 95A HF でモックを印刷し、寸法・装着感・ボタンの押し心地を先に確認
5. バッテリー（基板脇のくさび空隙、約40mAh）を BAT+ / BAT− へ
6. 本組み・装着評価

**TPU ならではの要点**: タクトスイッチの上に 0.8〜1.0mm の TPU 膜を一体成形すれば
膜自体がボタンになり、別部品もパッキンも要らない。

## v2 — 自作基板で小型化（v1 完成後）

v1 で仕様と操作感が固まってから着手する。

- MCU: **ISP1807-LR**（8×8×0.95mm、アンテナ・水晶・DC/DC内蔵）
- フラッシュ 16MB、充電IC は ISET を 10〜15mA に設定できるもの
- 電池: 曲面LiPo 15〜22mAh（厚1.6mm / 幅7mm / 弧長22〜29mm）
- **USB-C が載らない** → BLE OTA DFU と接点2端子＋マグネットドックが必須になる
- リジッドフレックス基板。剛体の島は 8mm 以下（内径18mmで 8mm の平板は中央が
  約0.9mm 浮く: サジッタ = R − √(R²−(弦/2)²) = 9 − √(81−16) ≒ 0.94）
- アンテナは印台の外周側（指から最も遠い位置）へ
